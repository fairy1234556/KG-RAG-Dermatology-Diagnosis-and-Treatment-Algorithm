# RQ1–RQ3 数据需求与 Ground Truth 需求说明 V1.0

## 0. 文档状态

- 阶段：Stage B0 — Data Requirement Analysis（数据需求分析）
- 目的：从已通过文献边界审查的 RQ1–RQ3 反推出实验所需的数据字段、Ground Truth、干预变量、控制变量和原始输出。
- 本阶段不冻结具体数据集、不冻结正式评价指标、不设计改进算法、不开始正式实验。
- 本文档通过后，进入 Stage B1：Dataset Audit（数据集审计）。

---

## 1. 当前研究问题

### RQ1：患者侧证据响应
当患者病例中的关键临床证据发生受控变化时，病例事实识别、知识图谱证据路径、候选疾病判断和生成式解释能否保持方向一致的跨层响应？

通俗理解：患者描述变了，系统后面的实体、路径、疾病判断和解释是否会合理地跟着变。

### RQ2：知识图谱侧证据响应
在患者病例保持不变的条件下，当外部知识图谱中的关键支持证据发生删除、削弱或冲突时，证据路径、候选疾病判断和生成式解释是否产生与外部证据变化相一致的响应，并在何种条件下出现由大语言模型参数知识补偿造成的证据依赖失配？

通俗理解：患者没变，只改知识图谱，系统是否真正受知识图谱影响，还是主要依赖大语言模型自身记忆。

### RQ3：双源证据交互
当患者病例证据与外部知识图谱证据处于一致、缺失或冲突等不同组合条件时，两类证据之间是否存在交互效应，系统在疾病判断和解释生成中表现出怎样的证据依赖模式？

通俗理解：患者证据和知识图谱证据同时变化、缺失或冲突时，系统最终更依赖哪一方，整个推理链是否仍然合理。

---

## 2. 实验基本单位

正式实验的基本单位不应是“单条病例”，而应是：

**母病例（Mother Case） × 患者侧干预条件 × KG 侧干预条件**

每个母病例必须具有唯一 `mother_case_id`，所有由其派生的病例变体必须保留该 ID，以防同源变体跨训练集、验证集和测试集造成数据泄漏。

### 2.1 Pilot 阶段建议
- 5–10 个高质量母病例；
- 优先覆盖多个疾病，而不是集中在单一疾病；
- 每个母病例选择 2–3 个患者侧干预和 2–3 个 KG 侧干预；
- 第一轮 Pilot 不要求完整笛卡尔积，只选择最能回答 RQ 的关键组合；
- 目标是发现 Failure Mode（失效模式），不是证明最终方法优越。

## 3. 每个母病例必须具备的 Ground Truth

### 3.1 病例级 Ground Truth

| 字段 | 必需性 | 说明 |
|---|---|---|
| `mother_case_id` | 必须 | 母病例唯一编号 |
| `source_dataset` | 必须 | 数据来源 |
| `source_case_id` | 必须 | 原数据集病例编号 |
| `case_text_original` | 必须 | 原始自然语言病例或可忠实转换为自然语言的结构化病例 |
| `gold_diagnosis` | 必须 | 原始标准诊断 |
| `valid_differentials` | 推荐 | 合理鉴别疾病集合；若数据源不支持则不得自行编造 |
| `data_provenance` | 必须 | 数据来源、版本、许可、处理方式 |
| `patient_group_id` | 条件必须 | 若同一患者有多条记录/多张图像，必须用于患者级隔离 |
| `kg_source_overlap_flag` | 必须 | 标记病例来源是否与构建 KG 的知识来源重叠 |

### 3.2 患者事实 Ground Truth

每一个可用于干预的临床事实必须记录：

| 字段 | 说明 |
|---|---|
| `fact_id` | 临床事实编号 |
| `fact_text` | 原始事实文本 |
| `fact_type` | 皮损形态、部位、症状、病程、检查、危险因素等 |
| `status` | `present / absent / missing` |
| `certainty` | 明确、疑似、否定等 |
| `source_span` | 在原病例中的文本位置或结构化字段来源 |
| `importance_source` | 重要性来源：数据集标注、指南/文献、专家等 |
| `is_candidate_key_fact` | 是否可作为关键干预事实 |
| `is_nonspecific_fact` | 是否属于弱/非特异事实 |
| `differential_relevance` | 是否具有鉴别意义；必须有来源依据 |

必须严格区分：
- `absent`：病例明确表示不存在；
- `missing`：病例没有提供该信息。

不得把“没有提到”自动解释为“不存在”。

### 3.3 实体映射 Ground Truth

| 字段 | 说明 |
|---|---|
| `fact_id` | 对应病例事实 |
| `gold_entity_id` | KG 中标准实体 ID |
| `gold_entity_name` | 标准实体名称 |
| `entity_type` | 实体类别 |
| `acceptable_aliases` | 可接受别名 |
| `mapping_status` | 可稳定映射 / 需人工映射 / KG 缺失 |
| `mapping_confidence_source` | 人工、数据集、词典或其他依据 |

该层用于独立评价 Semantic Anchor，而不是把后续疾病判断正确反推为实体映射正确。

### 3.4 KG 证据 Ground Truth

对每个病例—候选疾病组合，需要明确：

| 字段 | 说明 |
|---|---|
| `candidate_disease` | 当前被审查的疾病假设 |
| `path_id` | 标准证据路径 ID |
| `path_triples` | 路径中的三元组 |
| `path_relation_types` | 关系类型序列 |
| `evidence_role` | `support / counterevidence / nonspecific / unrelated` |
| `evidence_strength_source` | 数据/指南/文献/专家依据；Pilot 可先做定性 |
| `direct_or_indirect` | 直接路径 / 间接路径 |
| `removable_for_intervention` | 是否可以作为受控删除对象 |
| `alternative_path_exists` | 删除后是否仍存在合法替代路径 |
| `provenance` | KG 中该事实的来源 |

注意：
1. 删除 KG 事实前必须知道替代路径是否存在，否则无法区分“系统不会推理”和“图中已经没有可用信息”。
2. 不允许为了构造正式冲突条件而随意添加错误医学三元组。
3. 若需要冲突条件，应优先使用真实的竞争疾病证据、真实存在的矛盾来源或明确标记的 adversarial stress test（对抗压力测试）。

### 3.5 疾病判断 Ground Truth

Pilot 阶段建议分成两种模式：

#### 模式 A：固定候选疾病（主机制 Pilot）
- 将 `candidate_disease` 固定为目标疾病；
- 主要研究病例事实 → KG 路径 → 生成解释是否一致；
- 避免疾病预测模块成为额外混杂因素。

#### 模式 B：候选疾病排序（扩展 Pilot）
若系统具有稳定的候选疾病排序模块，则额外记录：
- `gold_diagnosis`
- `acceptable_differentials`
- 原始 rank
- 干预后 rank
- 是否出现医学上合理的方向变化

Pilot 不应强行规定“删除一个证据后疾病必须换成另一疾病”。优先定义方向性约束，例如：
- 删除支持证据后，该疾病支持程度不得因该证据而反向增加；
- 加入可靠反证后，疾病支持不得无解释地增强；
- 若仍有充分替代证据，排名不变可以是合理结果。

### 3.6 生成声明 Ground Truth

每个回答应拆成可核验医学声明。至少记录：

| 字段 | 说明 |
|---|---|
| `claim_id` | 声明编号 |
| `claim_text` | 声明文本 |
| `claim_type` | 病例事实、疾病支持、鉴别、风险、建议等 |
| `patient_fact_dependency` | 依赖哪些病例事实 |
| `kg_path_dependency` | 对应哪些 KG 路径 |
| `allowed_under_condition` | 在当前干预条件下是否允许出现 |
| `forbidden_under_condition` | 是否明确禁止出现 |
| `required_modification` | 是否必须删除、降级、改写或加入不确定性 |

最基础的禁止规则：
- 已从患者病例中删除的事实，不得继续被表述为“患者当前存在”；
- 被明确否定的事实，不得被生成模型改写成阳性事实；
- 已从 KG 中移除且不存在替代合法路径的证据，不得继续声称“根据当前 KG 证据”得到该结论；
- 知识库中的疾病一般特征不得冒充患者个体事实。

## 4. 患者侧干预设计

患者侧干预必须遵循“最小改动原则”，尽量只改变一个核心变量。

### P0：原始病例
不修改。

### P1：删除关键阳性事实
示例：删除“珍珠样结节”。

预期：
- 对应事实不再出现；
- 对应实体不应被识别；
- 依赖该事实的证据路径应消失或降级；
- 生成解释不得继续把该事实作为患者事实。

### P2：阳性事实 → 明确阴性
示例：“可见表面毛细血管扩张” → “未见明显表面毛细血管扩张”。

预期：
- 状态必须由 `present` 变为 `absent`；
- 不能被当作 `missing`；
- 若该事实对候选病重要，应形成反向或减弱信号。

### P3：仅保留弱/非特异事实
去掉强鉴别事实，只保留部位等弱信息。

目的：测试系统是否会在病例证据不足时依旧产生过强的特异性解释。

### P4：加入真实鉴别性事实
加入有可靠依据、倾向竞争疾病的关键事实。

要求：
- 必须来源于真实数据、权威知识或专家审核；
- 不能为了让答案翻转而任意编造症状。

---

## 5. KG 侧干预设计

患者病例必须保持完全不变。

### K0：完整 KG
原始知识图谱。

### K1：删除一个关键直接支持关系
例如删除候选疾病与关键皮损表现的直接边。

需记录：
- 删除的 triple_id；
- 是否有替代路径；
- 删除后图是否仍可回答当前问题。

### K2：删除多个高价值支持关系，仅保留弱/非特异证据
目的：观察系统是否会继续维持与完整 KG 相同强度的解释。

### K3：删除直接关系但保留合法替代路径
目的：区分“直接检索”与“替代路径利用”。

### K4：真实冲突/竞争证据条件
优先通过竞争疾病的真实支持路径或真实矛盾来源构造。
不得向正式医学 KG 注入虚假事实。

---

## 6. RQ1–RQ3 的控制变量

### RQ1
只改变患者病例证据，以下保持不变：
- KG 版本；
- 模型版本；
- Prompt；
- temperature；
- seed（若服务支持）；
- retrieval 参数；
- top-k；
- path ranking 参数；
- 系统配置。

### RQ2
只改变 KG 条件，以下保持不变：
- 患者病例原文；
- 候选疾病假设；
- 模型版本；
- Prompt；
- 推理参数；
- 检索配置。

### RQ3
采用成对/因子设计：
- 明确记录患者条件 P_i；
- 明确记录 KG 条件 K_j；
- 同一母病例所有组合共享其他系统设置；
- 同源条件必须在同一实验分组内完成，不得跨数据划分。

---

## 7. 每次运行必须记录的原始输出

正式指标此阶段不冻结，但 Pilot 必须保留以下原始数据：

### 输入与环境
- `run_id`
- `mother_case_id`
- `patient_condition`
- `kg_condition`
- 模型名称与版本
- temperature / seed / max tokens
- Prompt 版本
- KG 版本 hash
- 代码 commit hash

### 病例事实/实体层
- 输入病例文本
- 识别事实
- 识别实体 ID
- 实体置信度/规则来源

### KG 层
- 检索到的全部候选路径
- Path score
- Path rank
- Path 来源
- 被过滤路径
- 删除/扰动的 KG 元素

### 疾病层
若存在疾病排序：
- Top-k 候选疾病
- 排名
- 原始评分
- 干预前后变化

### 生成层
- 完整模型输出
- 原子声明
- 声明对应患者事实
- 声明对应 KG 路径
- 是否出现已删除/不存在的患者事实
- 是否出现已删除且无替代路径的 KG 事实
- 模型不确定性或限制性表达（如有）

### 性能与成本
- latency
- input/output tokens
- API error / retry
- 检索耗时
- 生成耗时

## 8. “合理响应”的方向性 Ground Truth

本研究不采用“只要输出发生变化就算好”的原则。

### 合理的情况
- 删除弱证据后，疾病 Top-1 不变，但支持声明减少；
- 删除一条支持路径后，系统使用其他合法替代路径；
- 增加强反证后，疾病排序下降或解释增加鉴别/不确定性；
- KG 缺失但模型仍答对，同时明确无法从当前 KG 获得对应证据。

### 不合理的情况
- 患者事实已经删除，解释仍声称患者存在该事实；
- 患者明确阴性，系统仍作为阳性支持；
- KG 关键事实已删除且无替代路径，却仍声称该知识来自当前 KG；
- 病例和 KG 都明显减弱候选疾病支持，模型的确定性却无依据显著升高；
- 干预发生后实体、路径、疾病、声明各层出现相互矛盾的变化。

因此 Pilot 主要评价“方向是否合理”，而不是预设每次干预都必须使最终疾病发生翻转。

## 9. 数据集进入 Stage B1 的最低要求

候选数据集至少应满足：

### 必须项
1. 有明确疾病标签；
2. 存在病例级临床事实，而非只有疾病标签；
3. 临床事实不能依靠疾病标签反向虚构；
4. 病例事实可以映射到当前 KG 或可明确标记 KG 缺失；
5. 能区分病例/患者，避免患者级数据泄漏；
6. 数据许可允许科研使用；
7. 能追溯数据来源和版本。

### 强烈推荐
1. 带结构化临床/皮肤镜特征标注；
2. 有自然语言病例描述；
3. 有阴性或缺失信息；
4. 有合理鉴别疾病信息；
5. 特征具有临床专家或权威来源定义；
6. 与当前 KG 构建来源相对独立。

### 直接判定为不适合作为核心主数据的情况
- 只有图像 + 疾病标签，且没有可独立验证的病例特征；
- 需要根据疾病标签“编写”患者症状才能用于实验；
- 同一知识来源同时负责病例生成、KG 构建和 Ground Truth，形成严重同源循环；
- 无法确认病例级/患者级独立性；
- 干预后医学合理性无法验证。

## 10. Pilot 的最低通过标准（Gate）

B4 Pilot 结束后，不以“模型是否提升”作为通过标准，而检查以下问题：

### Gate P1：可构造性
至少 5 个母病例能构造医学合理的患者侧和 KG 侧受控变体。

### Gate P2：映射可用性
关键病例事实能够稳定映射到 KG 实体，且映射错误不会成为绝对主导噪声。

### Gate P3：路径可控性
能够明确知道某次 KG 干预删除了哪些路径，且能够验证替代路径是否存在。

### Gate P4：输出可比较性
不同条件下输出能够拆解为可核验声明，不因格式随机性导致无法比较。

### Gate P5：存在可研究现象
至少观察到一种稳定、可重复的跨层不一致或证据依赖问题，例如：
- 病例事实变但路径不变；
- 路径变但生成声明不变；
- KG 关键证据消失但模型仍声称来自 KG；
- 病例与 KG 冲突时模型出现稳定偏向；
- 依赖参数知识导致外部证据变化对输出异常不敏感。

如果 P1–P4 通过但 P5 完全不存在，应重新评估 RQ 的实际价值，而不是人为制造问题。

---

## 11. B0 当前明确不冻结的内容

以下内容必须等 Stage B1–B4 后再决定：

- 最终数据集；
- 最终疾病范围；
- 正式病例数量；
- 最终 Path scoring 公式；
- 正式评价指标；
- 正式 Baselines；
- 新算法/新模块；
- 是否修改现有 `relation_weights.yaml`；
- 是否加入疾病自动预测模块；
- 是否使用医生人工评分作为主要评价。

---

## 12. B0 → B1 进入条件

只有满足以下条件才进入数据集审计：

1. RQ1–RQ3 均能对应明确输入变量和输出变量；
2. 已定义病例事实、实体、KG 路径、疾病与声明五层 Ground Truth；
3. 已明确患者侧和 KG 侧干预边界；
4. 已明确正式实验不得通过标签反推病例事实；
5. 已明确冲突条件不得依赖虚假医学 KG；
6. 已明确 Pilot 的目的为发现 Failure Mode，而不是验证预设算法；
7. 所有正式实验数据均需记录来源、版本和同源风险。

满足上述条件后，Stage B0 可标记为“设计完成”，进入 Stage B1：候选数据集逐项审计。
